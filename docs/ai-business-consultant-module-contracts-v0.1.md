# AI商业顾问核心节点契约与实施分层 v0.1

更新日期：2026-09-13
状态：方案设计稿，尚未进入代码实现

## 1. 文档目的

将 AI商业顾问从“概念框架”进一步拆成可以逐步执行的节点。每个节点都必须明确：

- 解决什么问题；
- 输入什么资料；
- 输出什么结果；
- 哪些内容是事实、假设和推断；
- 哪一步必须由人确认；
- 用什么标准判断节点有效；
- 什么时候才值得自动化。

本文件不代表已经开始开发，也不代表最终对外产品已经确定。

## 2. 总体结构

```text
项目状态与事实库
        ↓
资料导入与来源标记
        ↓
能力盘点
        ↓
客户与问题识别
        ↓
商业画布
        ↓
商业假设排序
        ↓
访谈与问题验证
        ↓
最小实验设计
        ↓
人工 + AI 小交付
        ↓
结果、付费与交付成本记录
        ↓
复盘与继续/调整/停止决策
        ↓
流程固化、服务化、Skill/Agent 化
```

新媒体不是主流程的起点，而是增长与验证层的渠道：

```text
商业问题明确后
→ 用内容展示问题理解和能力
→ 获取线索或熟人试用
→ 进入访谈、诊断或小交付
```

## 3. 通用节点契约

每个节点统一使用以下字段：

```text
节点名称
节点目标
输入
输出
事实
假设
证据来源
AI可做
人工必须做
验收标准
失败回退
记录位置
自动化等级
```

### 3.1 证据标记

- A：真实客户问题 + 实际交付结果 + 付费或明确预算/采购承诺。
- B：真实客户问题或明确产品价格，但结果证据不足。
- C：个人判断、市场观察、流量、工具热度或收入传闻，只能形成假设。

AI不能自动把 C 级材料升级为商业结论。

### 3.2 人工确认门

以下节点必须保留人工确认：

1. 能力是否真实且当前可交付；
2. 客户问题是否来自真实事件；
3. 商业画布中的客户、价值和价格是否只是假设；
4. 对外报告的事实和来源；
5. 客户方案、结果承诺和高风险回复；
6. 是否继续、调整或停止一个实验。

## 4. 核心节点定义

### N0：项目状态与上下文

**目标**：让每次工作从当前状态继续，而不是重新讨论已经确认的方向。

**输入**：`business/STATE.md`、`founder-profile.md`、相关画布、决策日志和最近实验。

**输出**：当前阶段、已确认决策、未验证假设、当前唯一下一步。

**AI可做**：摘要、冲突检测、关联文件提示。

**人工必须做**：确认当前目标和优先级。

**验收标准**：输出不应覆盖最新用户决策，不应把历史假设写成事实。

**记录位置**：`business/STATE.md`。

**自动化等级**：P0，直接使用现有文件。

### N1：资料导入与来源标记

**目标**：把简历、课程、项目、客户资料转换为可分析文本，并保留来源。

**输入**：Markdown、TXT、PDF、Word、Excel、PPT、CSV，以及经授权的客户资料。

**输出**：带来源、时间、文件哈希和确认状态的 Markdown/JSON 资料卡。

**AI可做**：文本转换后的分段、分类、摘要和重复检测。

**人工必须做**：确认资料授权、敏感信息和关键事实。

**验收标准**：任何结论都能追溯到具体文件或原话；转换失败时保留原文件并提示人工处理。

**复用组件**：`microsoft/markitdown`。

**必须修改/补充**：来源标记、脱敏提醒、人工确认状态，不把转换结果自动视为事实。

**自动化等级**：P0/P1。

### N2：能力盘点

**目标**：识别发起人或客户真正能够交付的能力，而不是罗列职位名称或工具名称。

**输入**：简历、项目记录、交付过程、客户对象、交付物、结果证据。

**输出**：能力卡。

能力卡至少包含：

```text
能力名称
服务对象
典型场景
输入
动作
判断点
交付物
结果证据
当前可复现程度
AI可辅助部分
人工边界
```

**AI可做**：从资料中提取动作、对象、交付物和重复模式。

**人工必须做**：确认本人实际贡献、当前能力、案例可公开性和结果归属。

**验收标准**：能力必须能转换成一个具体客户任务，不能只写“懂运营”“会做IP”“会用AI”。

**自动化等级**：P0，先用模板和 AI 草稿。

### N3：客户与问题识别

**目标**：把宽泛客户标签拆成可访谈、可交付、可观察结果的具体任务。

**输入**：历史客户经验、客户原话、业务流程、损失、现有解决方案和预算信号。

**输出**：客户问题卡。

```text
客户类型
具体场景
触发事件
当前任务
问题表现
造成损失
现有替代方案
客户是否已经投入资源
期望结果
可获得资料
验证方式
```

**AI可做**：聚类、归纳、对比不同客户事件。

**人工必须做**：判断问题是否真实、是否属于客户愿意解决的问题，以及是否有交付边界。

**验收标准**：问题必须能被一个客户用具体事件描述，不能只停留在“想涨粉”“想变现”“想用AI”。

**当前候选**：P1 内容到有效咨询/预约的断点。

**自动化等级**：P0。

### N4：商业画布

**目标**：将客户、问题、价值、渠道、交付和收入关系放在同一张可更新的画布中。

**输入**：能力卡、客户问题卡、替代方案、渠道、交付成本和证据。

**输出**：带证据等级的商业画布。

传统画布字段之外，增加：

```text
事实
假设
证据等级
待验证问题
验证实验
成功标准
停止标准
```

**AI可做**：生成初稿、检查字段冲突、提示缺失信息。

**人工必须做**：确定暂时不做的客户、结果和承诺。

**验收标准**：画布中的关键字段不能没有事实/假设标记；价格不能被 AI 擅自确定为市场结论。

**复用参考**：`ojfbot/lean-canvas`、`josevilar-qbioai/agent-canvas-model`，只参考交互和字段组织。

**自动化等级**：P0，直接使用现有 Markdown 模板。

### N5：商业假设与优先级

**目标**：将多个可能方向排序，选择验证成本最低、信息价值最高的一条。

**输入**：商业画布、能力卡、客户问题卡、资源限制和用户偏好。

**输出**：假设卡和排序表。

```text
假设
目标客户
客户任务
预期价值
最小交付
验证成本
验证周期
成功信号
停止信号
当前证据等级
下一步
```

排序优先考虑：

```text
问题损失
× 发生频率
× 资料可得性
× 结果可观察性
÷ 验证成本
```

这只是排序启发式，不是数学真理。

**AI可做**：比较候选方向、发现冲突、生成验证选项。

**人工必须做**：确认时间、预算、销售和交付边界。

**验收标准**：每条假设必须对应一个最小实验，不能只得到“建议继续研究”。

**自动化等级**：P0。

### N6：客户访谈与问题验证

**目标**：取得客户对真实事件、现有方案、损失、尝试和预算的具体描述。

**输入**：客户基本背景、访谈提纲、录音/文字记录、客户授权。

**输出**：访谈记录、原话、问题卡更新、证据等级变化。

**AI可做**：转录、摘要、原话提取、问题分类和矛盾提示。

**人工必须做**：主持访谈、追问具体事件、确认引用、保护隐私。

**验收标准**：不能把“听起来不错”“以后可以合作”直接计为付费证据；必须记录具体行为、投入或承诺。

**自动化等级**：P0，AI只整理，不自动替代访谈。

### N7：最小实验设计

**目标**：用最小成本验证客户是否会采用解决方案，并尽快获得结果或停止信号。

**输入**：假设卡、客户资料、当前基线、可用时间和交付边界。

**输出**：实验卡。

```text
实验目标
实验对象
实验周期
输入资料
人工步骤
AI步骤
客户需要执行什么
观察指标
成功标准
停止标准
预计耗时
风险
```

**AI可做**：拆分步骤、生成记录表、提出指标候选。

**人工必须做**：确认实验不会承诺无法控制的结果，并确认客户配合程度。

**验收标准**：实验周期一般控制在 1—14 天，必须能观察到行为或交付采用信号。

**自动化等级**：P0。

### N8：人工 + AI 小交付

**目标**：在不开发完整产品的情况下，完成一次有边界、可验收的真实交付。

**输入**：客户授权资料、问题卡、实验卡、交付模板。

**输出**：客户能直接使用的交付物，例如：

- 内容研究与选题包；
- 内容—咨询断点诊断；
- 回复与跟进流程草稿；
- 课程模块和产品结构草稿；
- 私域 SOP 草稿；
- 数据复盘报告。

**AI可做**：整理、比较、生成初稿、发现遗漏、形成候选方案。

**人工必须做**：选择优先问题、解释业务含义、审核事实、对外沟通和最终交付。

**验收标准**：客户是否采用、修改次数、进入执行的比例、交付耗时和继续使用意愿必须记录。

**自动化等级**：P0，先人工 + AI。

### N9：证据、结果与成本记录

**目标**：区分“做完了”与“产生了客户价值”。

**输入**：实验记录、交付物、客户反馈、执行结果、耗时和费用。

**输出**：证据卡和交付账本。

```text
客户问题是否确认
交付是否完成
客户是否采用
客户是否执行
结果是否可观察
人工耗时
AI耗时/成本
修改次数
付费或预算信号
复购/转介绍信号
```

**验收标准**：至少同时记录过程指标、客户行为指标和商业结果指标；不以播放量或 AI 输出字数代替客户价值。

**自动化等级**：P0，Markdown/JSON 即可。

### N10：复盘与决策

**目标**：决定继续、调整、暂停或停止某个方向。

**输入**：假设、实验、证据、成本和客户反馈。

**输出**：复盘报告和下一步决策。

```text
原假设
实际发生
证据变化
哪里有效
哪里失败
失败原因
继续/调整/停止
下一轮只改什么
```

**AI可做**：对照计划与结果、发现遗漏、生成复盘草稿。

**人工必须做**：做最终商业判断。

**验收标准**：每轮实验只允许形成清晰决策，不以“继续观察”替代行动。

**自动化等级**：P0。

### N11：产品化与自动化候选

**目标**：在流程已经重复且稳定后，判断应该产品化为什么形式。

**输入**：多次交付记录、输入输出稳定性、人工修改量、客户采用率、付费情况和交付成本。

**输出**：产品化评估。

可能形态：

```text
一次性诊断
短周期陪跑
结果型服务
课程/工作坊
模板/Skill
Agent
软件
```

**自动化前提**：

```text
同一任务重复出现
+ 输入输出边界稳定
+ 失败模式可识别
+ 人工判断点清楚
+ 客户持续采用
+ 有明确付费
```

**自动化等级**：P2，当前不开发。

## 5. 新媒体节点在整体框架中的位置

新媒体属于增长与验证层，不是商业顾问的根节点。

### 内容

输入：客户问题、真实案例、方法判断、公开资料。

输出：独立成立的内容、选题、脚本和发布记录。

AI可做：对标研究、选题聚类、脚本初稿、评论分类、数据复盘。

人工必须做：真实性、观点取舍、案例授权、最终表达和发布。

### 直播

输入：内容主题、直播话题、FAQ、实时评论或评论记录。

输出：候选回复、问题分类、直播复盘。

第一版只做：人工粘贴评论 → AI 分类和候选回复 → 人工审核发送。

第一版不做：自动读取直播间、自动回复、自动逼单、自动投流。

### 线索与销售

输入：评论、私信、预约和客户资料。

输出：线索摘要、客户阶段、下一步建议和跟进记录。

AI只生成建议，不直接发送或承诺结果。

## 6. 开发分层

### P0：先固化业务流程

```text
Markdown/Git
+ 现有模板
+ 一个模型接口
+ 人工确认
```

目标：跑通 N0—N10 一次。

### P1：减少重复整理

```text
MarkItDown
+ Pydantic/Pydantic AI
+ 简单 CLI
```

目标：资料导入稳定，输出字段稳定，缺失信息能提示。

### P2：流程变复杂后再接

```text
LangGraph
+ GPT Researcher
+ Streamlit
+ Langfuse
+ Promptfoo
+ LiteLLM
```

每个组件必须对应一个已经出现的实际瓶颈，不能因为项目热门而接入。

## 7. MVP验收标准

第一版不是验收“Agent 是否聪明”，而是验收：

1. 是否能从当前状态继续工作；
2. 是否能把资料整理成能力卡；
3. 是否能形成一份事实/假设分离的商业画布；
4. 是否能选出一个最小实验；
5. 是否能记录人工 + AI 的交付过程；
6. 是否能记录客户采用、结果、成本和付费信号；
7. 是否能产生继续、调整或停止决策；
8. 是否没有在没有证据时自动编造客户、价格和结果。

## 8. 本阶段边界

本阶段只做调研和方案设计。未获得用户确认前：

- 不写代码；
- 不安装依赖；
- 不克隆第三方仓库；
- 不接入平台账号；
- 不自动发布、私信、直播回复或销售。
