# 商业顾问框架 v2：战略、商业模式、运营与反馈

公开整理：2026-10-05；沿用框架 v2 与全年节日/每日热点选题方法。范围：顾问工作的模型、导航与资产归属；不是业务转向，也不是新建产品或Agent的指令。

## 1. 总体逻辑与黄金圈

- WHY：减少无效投入，发现值得解决的问题，形成可持续的客户价值。
- HOW：明确选择，提出可检验假设，小步执行，用证据修正判断；重要承诺由人确认。
- WHAT：战略选择图、商业模式画布、运营交付设计、实验与经营反馈，以及执行这些工作的既有资产。

```text
战略选择 → 商业模式 → 运营交付
   ↑          ↑          ↑
   └──── 验证与经营反馈 ────┘
```

这三个对象分别回答“在哪里做、凭什么做”“价值如何创造、交付和获取”“谁以什么流程与能力兑现承诺”。验证是贯穿三者的反馈机制，不是第四个业务部门；AI和Skill是资源、活动与能力，不与战略并列。

这是参考原始模型形成的项目适配结构，不是贝恩、麦肯锡或BCG的统一官方框架。三者不是互斥目录：商业模式已经包含运营逻辑，运营设计进一步展开其中的资源、活动、伙伴、责任与治理。资产只维护一份，通过主归属和交叉引用表达多种用途。

本公开版采用上述三部分结构，不附带个人工作状态或历史任务。

## 1.1 系统、应用场景与成果边界

- **顾问系统**：用于分析、设计、验证与持续经营业务的工作方式；不是具体产品，也不是Skill目录。
- **应用场景**：用这套系统处理的一项具体业务。业务自身会同时遇到战略、商业模式和运营问题，不能整体归入“渠道”。
- **两类成果**：业务结果（客户价值、交付、交易及持续性）与系统沉淀（经实践检验的方法、流程、工具与Skill）分别记录；有方法不代表有商业结果，有单次结果也不代表方法普遍有效。
- **可迁移与不可直接迁移**：通用问题与框架可跨赛道适配；行业知识、客户任务、竞争条件、能力适配与商业假设需要重新补足和验证，不宣称跨赛道能力已经成立。
- **自用与对外服务**：实践中使用顾问系统，不自动构成对外经营咨询业务或软件产品化的决策。这些仍需独立画布与验证。

三部分不是必须按顺序全部完成的阶段：可以从真实交付暴露的问题返回模式或战略，但不能省略对应的证据检查。黄金圈是解释目的、方法与产出的视角，不与三个主分支机械一一对应。

## 1.2 新媒体、人的能力与Skill的归属

- 新媒体作为整项业务：贯穿战略选择、商业模式、运营交付与反馈。
- 新媒体作为具体用途：传播是渠道；可购买的内容或知识可能是供给的一部分；内容库与账号可能是资源；研究、制作、服务是活动。每种用途按具体业务判断，不一概认定成立。
- 人的能力在战略中影响机会选择与取胜条件，在商业模式中属于资源或通过活动兑现价值，在运营中通过职责、流程、质量和工具落实。
- AI Skill只承载部分可复用方法，不等于人的完整能力，不替代行业经验、重要判断、验收或对外责任。

## 1.3 展示与下钻规范

根节点为“商业顾问”，仅设战略选择、商业模式、运营交付三个主分支；反馈单独标为贯穿机制，应用场景也不列成第四分支。总览采用可折叠树；节点详情分开呈现定义、现有记录、缺口、下一步、资产关联与模型来源。九格保留实际空间布局作为详情中的辅助视图。

最小问题指当前管理粒度下能独立回答、记录和核验的问题，不宣称不可继续拆分。新拆问题若只有上级共用资料，必须明确“待逐项核验”，不得自动继承上级完成状态。已有资产按主归属加交叉用途导航，保持原目录和暂停边界；详细项目填充及HTML仅存本地私有范围。

## 2. 战略选择：决定做什么、不做什么

参考贝恩的目标、竞争范围、取胜方式与实现路径问题逻辑，形成以下项目检查组；不是所谓“贝恩五步法”。

| 检查组 | 继续拆解 | 需要形成的输出 |
| --- | --- | --- |
| 使命与范围 | 目的、边界、成功标准 | 目标与不做清单 |
| 市场与竞争 | 情境、替代方案、变化与风险 | 来源可追溯的选择依据 |
| 客户与场景 | 人群、任务、购买角色、触达可能 | 优先细分与使用情境 |
| 取胜与能力 | 客户结果、差异、现有能力及依赖 | 可检验的优势假设 |
| 优先级 | 重要性、不确定性、代价与可逆性 | 下一项判断与验证门槛 |

研究材料、流量或工具热度不自动构成需求证明。

## 3. 商业模式：实际使用九格，而不只登记“已有画布”

采用Strategyzer的Business Model Canvas。每个候选商业模式单独表达，不把全项目的所有资产硬塞成一个已成立的模式。

| 标准格 | 要回答的问题 | 下钻字段 |
| --- | --- | --- |
| 客户细分 Customer Segments | 为谁创造价值 | 人群、使用者/付款者、任务触发、可触达性与优先级 |
| 价值主张 Value Propositions | 为什么选择这项供给 | 结果、痛点缓解、替代方案、承诺凭据、交付载体 |
| 渠道 Channels | 怎样发现、评估、购买、获得和使用 | 认知、评估、购买、交付、售后阶段 |
| 客户关系 Customer Relationships | 怎样建立并维持关系 | 建立、支持、留存、反馈和复购机制 |
| 收入来源 Revenue Streams | 谁为什么付多少钱 | 付款者、计价单位、价格、支付时点、重复收入 |
| 核心资源 Key Resources | 兑现价值需要什么 | 人力、知识/内容、技术、资金、权利与可用性 |
| 关键活动 Key Activities | 必须重复做好哪些事 | 研究、获客、成交、制作交付、质量与复盘 |
| 重要伙伴 Key Partnerships | 哪些依赖需由外部提供 | 角色、资源、激励、协议、替代性与风险 |
| 成本结构 Cost Structure | 价值实现需要哪些投入 | 固定/变动、全工时、获客、交付、返工、现金支出 |

每个字段分别呈现：模型含义 → 现有事实或材料 → 假设/验收边界 → 缺失证据 → 最小补充方式。字段有文字不表示市场验证完成，不用虚构百分比混淆文档完整度和商业成立度。

补充工具：
- 价值主张工具：核对客户任务/痛点/收益与产品服务/痛点缓解/收益创造的对应；不是把技能名称当成客户价值。
- 供给定义：对象、结果、范围、验收、费用/支付、支持与责任边界。
- 跨格检查：客户—价值、价值—渠道关系、价值—资源活动伙伴、收入—付款者、收入—成本、结果—模型修正。

## 4. 运营交付：把承诺变成可重复结果

采用贝恩特定官方文章的五个运营模型要素，不声称所有贝恩材料都只有五项。

| 原始要素 | 项目适配检查 |
| --- | --- |
| Structure 结构 | 任务范围、业务与能力边界、协作接口 |
| Accountabilities 责权 | 谁决策、谁执行、谁验收；人和工具的责任不能混同 |
| Governance 治理 | 权限、优先级、资源配置、指标、风险和停止条件 |
| Ways of working 协作方式 | 输入输出、交接、反馈、版本与变更 |
| Capabilities 能力 | 人、流程、技术组合是否可重复地产生合格结果 |

最小交付链：输入与授权 → 任务定义 → 人/Skill执行 → 质量复核 → 验收与记录 → 反馈。麦肯锡7-S仅用来补充检查组织要素是否协调，不代替九格或强制增加七个部门。

## 4.1 内容研究与生产：全年节日与每日热点选题管理

**目标：** 做新媒体视频时，将可提前安排的节日内容与每天出现的相关热点放在同一条全年热点时间轴中，提前准备并持续补充，而不是临近节日才开始找选题。

- **全年节日底表：** 整理中国及世界的重要节日，核对当年的具体日期、适用国家或地区及来源，按时间顺序建立全年热点时间轴；农历或其他日期浮动的节日逐年核验，不直接沿用上一年日期。
- **每个节日对应话题与内容：** 为各节日整理相关话题、与当前受众及账号方向的关联、候选视频选题、参考内容与素材需求。候选内容与已确认制作内容分开，不要求每个节日都发布视频。
- **至少提前一周筹备：** 每个拟制作的节日内容，以节日当天为T日，将最晚启动筹备日期设为T−7天，并列出选题确认、资料与素材准备、脚本、拍摄剪辑、审核及计划发布日期；制作周期更长的内容再向前安排。每次更新时检查未来7天的节点，已到筹备日期但未启动的项目明确标记待处理。
- **每日热点补充：** 每天搜集当天与受众、行业及内容方向相关的热点信息，记录事件发生日期、采集日期、来源、核验状态、时效及可用话题，补入同一条全年时间轴。与节日有关的热点关联对应节点，无关的独立热点按日期单列，不为填满日历而硬凑关联。
- **统一记录与更新：** 时间轴至少包含日期、节日或热点名称、适用地区、关联话题、内容方向、资料来源、筹备启动日、计划发布日期、制作状态及下一步；事实、候选想法、制作决定与实际反馈分开记录。热点失效或事实变化时及时修正，不以热度代替商业需求证据。

本节属于“运营交付 → 内容研究与生产 → 选题规划与排期”，不新增顶层框架或独立Skill。具体账号、内容和采集记录保存在经核实Git忽略的私有任务目录；这里只维护通用流程。每日采集与提前筹备是工作频率要求，不代表后台自动化已配置或全年资料已整理完成；不自动发布内容。

## 5. 验证与经营反馈：不是在图上画一圈

- 设计层：九格逻辑相互支持，交付和交易路径能解释。
- 证据层：发现触达 → 问题匹配 → 范围报价 → 支付/承诺分别记录 → 交付验收 → 采用/复购 → 成本与选择更新。实际支付可以预付、分期或交付后，不强制所有业务只有一种顺序。
- 实验卡：假设、测试方法、指标、事先阈值；附权限、成本和停止条件。
- 学习卡：观察、解释、证据限制、保留/修改/停止及对应画布格。
- 经营指标：明确分母、时间窗口、客户/订单口径、退款和实际工时。缺数据写未知，不把样例当成交易。

方法卡已经存在不代表实验已执行；支付不等于有效交付，有效交付也不自动证明可持续获客或复购。

## 8. 展示时怎么说清楚

结构名称与阅读用语可以分开：保留战略选择、商业模式、运营交付及九格对应关系，具体标题和问题用完整、日常的中文表达。先说明是谁、遇到什么事、怎么处理，再按需显示专业名称；不要求读者先学术语才能看懂框架。

节点详情分别交代：这项说的是什么、目前知道什么、还有什么没弄清楚、接下来如何弄清楚。上级有相关资料不等于每个小问题都已有答案。示例与实际记录分开，换措辞不补写客户事实、不把设想改成已验证结果。
