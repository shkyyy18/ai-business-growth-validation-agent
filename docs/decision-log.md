# 决策记录

## 2026-09-11：确定项目起点

### 讨论背景

项目发起人最初想做一个新媒体 Agent，后来逐步澄清：自己的优势在抖音账号、内容、直播、知识付费、本地生活销售和运营；同时多年没有持续做新媒体，对当前网感和市场缺乏把握。

### 讨论过的路径

1. 先搭建完整新媒体框架，再逐步落地优化。
2. 直接从 GitHub 高 Star 项目开始改造。
3. 先调研市场、目标人群、产品和变现案例。

### 当前决策

采用一条连续验证链，而不是三选一：

```text
先画完整链路骨架
→ 用 AI 提升自己的内容生产效率
→ 发布内容获取流量和线索
→ 从评论、私信和访谈发现问题
→ 用 AI 辅助人工解决问题
→ 验证小额付费
→ 再产品化和 Agent 化
```

市场调研不再是一个脱离内容的长期任务，而是嵌入内容发布、线索收集和客户沟通中。GitHub 项目暂时只做技术候选库，等重复需求出现后再选型。

### 关键判断

- “所有想学 AI 的人”可以作为上层内容受众，但不能直接作为第一款产品的客户定义。
- 内容既是获客渠道，也是市场研究工具。
- AI 首先用于提高项目发起人自己的生产效率；对外产品方向由真实客户问题决定。
- 现在应该建立一个内部项目 Agent，但它的第一版职责是帮助研究、生产、记录和复盘，不是直接做一个面向市场销售的软件。

### 待验证事项

- 哪些内容主题带来目标人群的有效互动。
- 哪些人愿意预约诊断或参加低价工作坊。
- 哪个客户问题重复出现且能在 7—14 天内交付。
- 哪些交付步骤可以稳定交给 AI 或工作流。

## 2026-09-11：以完整新媒体框架作为主线

项目先搭建完整的新媒体经营框架，内容只是其中一个获客模块，Agent 和 Skill 是嵌入各模块的能力层。

```text
业务与定位 → 客户与场景 → 产品与成交 → 渠道与流量
→ 内容与直播 → 线索承接与销售 → 交付与复盘 → Agent/Skill 按需加入
```

采用这个顺序，是为了按模块掌握进度，并避免先开发工具再寻找使用场景。先让链路手工运行，再根据真实重复工作选择自建或市场上成熟的 Agent/Skill。

每个模块都必须有目标、输入、输出、指标、记录位置和状态；状态按“未开始、已设计、已手工验证、已稳定运行、可自动化、可复制交付”推进。

## 2026-09-11：调整研究方法，优先借鉴成熟开源项目

项目发起人指出，当前不应先凭经验猜测对标账号、内容方向或自建框架细节。后续采用“成熟项目借鉴 + 本项目框架映射”的方法：

1. 先在 GitHub 等公开来源检索成熟的 Agent、Skill、内容生产、社交媒体运营和营销自动化项目。
2. 优先查看真实代码、文档、Issue、Release、使用方式和维护状态；Star 只作为初筛信号，不能单独作为商业需求证据。
3. 将成熟项目的模块、流程、输入、输出、指标和边界映射到本项目八模块。
4. 先输出项目清单和结构化分析报告，提交项目发起人确认。
5. 确认后再决定哪些内容模块、Skill 或 Agent 值得借鉴、改造或暂不采用。
6. 对标账号和内容研究仍然保留，但应在明确研究目标后进行，不能用主观猜测代替外部证据。

当前暂停：自行设计更多内容草稿、凭经验确定对标账号或直接推进发布测试。

## 2026-09-12：Agent 从“新媒体 Agent”升级为“商业增长验证 Agent”

项目发起人指出，今天讨论的才是 Agent 的上层框架：商业闭环、AI 变现和新媒体之间的关系。确认新媒体只是获客、信任建立和市场验证手段之一，不应作为 Agent 的总框架。

当前推荐 Agent 正式名称为：**AI 商业增长验证 Agent**（AI Business Growth Validation Agent），内部简称“商业增长 Agent”。其核心任务是帮助项目发起人及未来客户发现真实商业问题，设计 AI 增强方案，通过人工交付、结果和付费证据验证，再逐步产品化和自动化。

新结构调整为四层：商业问题层（Why）、业务闭环层（What）、增长与验证层（How，新媒体位于此层）、AI 增强与复制层。详细方案见 `docs/agent-repositioning-and-structure.md`。

在新结构确认前，原“新媒体八模块”降为增长与验证层中的一个实现框架，不再作为 Agent 的顶层结构。
