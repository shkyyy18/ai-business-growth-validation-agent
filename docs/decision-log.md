# 决策记录

## 2026-09-11：确定项目起点

### 讨论背景

项目发起人最初想做一个新媒体 Agent，后来逐步澄清：自己的优势在抖音账号、内容、直播、知识付费、本地生活销售和运营；同时多年没有持续做新媒体，对当前网感和市场缺乏把握。

### 讨论过的路径

1. 先搭建完整新媒体框架，再逐步落地优化。
2. 直接从 GitHub 高 Star 项目开始改造。
3. 先调研市场、目标人群、产品和变现案例。

### 当前决策

采用一条连续验证链，而不是三选一：

```text
先画完整链路骨架
→ 用 AI 提升自己的内容生产效率
→ 发布内容获取流量和线索
→ 从评论、私信和访谈发现问题
→ 用 AI 辅助人工解决问题
→ 验证小额付费
→ 再产品化和 Agent 化
```

市场调研不再是一个脱离内容的长期任务，而是嵌入内容发布、线索收集和客户沟通中。GitHub 项目暂时只做技术候选库，等重复需求出现后再选型。

### 关键判断

- “所有想学 AI 的人”可以作为上层内容受众，但不能直接作为第一款产品的客户定义。
- 内容既是获客渠道，也是市场研究工具。
- AI 首先用于提高项目发起人自己的生产效率；对外产品方向由真实客户问题决定。
- 现在应该建立一个内部项目 Agent，但它的第一版职责是帮助研究、生产、记录和复盘，不是直接做一个面向市场销售的软件。

### 待验证事项

- 哪些内容主题带来目标人群的有效互动。
- 哪些人愿意预约诊断或参加低价工作坊。
- 哪个客户问题重复出现且能在 7—14 天内交付。
- 哪些交付步骤可以稳定交给 AI 或工作流。

## 2026-09-11：以完整新媒体框架作为主线

项目先搭建完整的新媒体经营框架，内容只是其中一个获客模块，Agent 和 Skill 是嵌入各模块的能力层。

```text
业务与定位 → 客户与场景 → 产品与成交 → 渠道与流量
→ 内容与直播 → 线索承接与销售 → 交付与复盘 → Agent/Skill 按需加入
```

采用这个顺序，是为了按模块掌握进度，并避免先开发工具再寻找使用场景。先让链路手工运行，再根据真实重复工作选择自建或市场上成熟的 Agent/Skill。

每个模块都必须有目标、输入、输出、指标、记录位置和状态；状态按“未开始、已设计、已手工验证、已稳定运行、可自动化、可复制交付”推进。
