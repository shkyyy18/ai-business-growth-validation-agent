# 新媒体经营框架

本项目先搭建完整的新媒体经营框架，再逐模块加入内容、Agent 和 Skill。内容是获客模块，不等于整个项目。

## 总体链路

```text
业务与定位
→ 客户与场景
→ 产品与成交理由
→ 渠道与流量
→ 内容与直播
→ 线索承接与销售
→ 交付与客户成功
→ 数据复盘与迭代
→ 自动化、Agent 和 Skill
```

每个模块都要回答：目标是什么、当前怎么做、用什么指标判断、哪些步骤可以由 AI 提效。

框架先作为项目容器搭建，不要求一开始填满。每个模块按照 `docs/module-template.md` 逐步补充，内容可以来自已有经验、市场观察、客户沟通、实验和交付记录。后续可以根据证据调整模块定义、顺序和边界。

## 八个模块

1. **业务与定位**：记录能力资产、资源、限制、阶段目标和暂时不做的事。
2. **客户与场景**：记录客户身份、任务、痛点、损失、现有方案和付费信号。
3. **产品与成交**：把问题转成可交付结果，先人工验证，再决定课程化或软件化。
4. **渠道与流量**：管理抖音及其他平台，记录受众来源、流量入口和线索路径。
5. **内容与直播**：建立信任、测试问题假设、获取线索；直播承担答疑、诊断和成交。
6. **线索与销售**：记录评论、私信、表单、预约、诊断、报价和成交。
7. **交付与客户成功**：记录输入、步骤、交付物、反馈、结果证据、复购和转介绍。
8. **数据复盘与迭代**：按周复盘曝光、行为、收入和交付指标，形成下一轮实验。

## Agent 和 Skill 的位置

Agent 和 Skill 嵌入上述模块，不另起一条业务线。它们可以用于访谈整理、痛点分类、选题脚本、直播复盘、线索摘要、SOP 生成和数据周报。只有重复、高频、规则清晰的工作才进入自动化候选。

## 推进顺序

### 阶段 1：框架可运行

为八个模块写清输入、输出、指标和记录位置。

### 阶段 2：手工跑通一轮

选择一个渠道、一个内容实验和一个线索入口，跑过“发布—承接—沟通—交付—复盘”。

### 阶段 3：找重复工作

记录耗时、重复次数、错误和人工判断点，形成自动化需求清单。

### 阶段 4：逐个加入 Agent 或 Skill

每个能力都要有输入、输出、验收标准和失败回退方式。

### 阶段 5：形成可复制服务

将已经验证的流程整理成服务包、课程、陪跑或软件功能。

## 当前进度板

| 模块 | 当前状态 | 下一步 |
|---|---|---|
| 业务与定位 | 已设计 | 核验抖音账号现状和受众，准备三类内容假设测试 |
| 客户与场景 | 未验证 | 收集评论、私信和访谈原话 |
| 产品与成交 | 未定 | 由真实痛点和交付结果决定 |
| 渠道与流量 | 已设计 | 人工核验账号现状和受众，建立渠道基线 |
| 内容与直播 | 已设计 | 先借鉴成熟项目和外部内容方法，确认后再做对标内容与改写测试 |
| 线索与销售 | 已设计 | 用统一模板承接三类内容测试，推进一次人工诊断 |
| 交付与客户成功 | 有新媒体项目经验 | 记录可复用 SOP |
| Agent/Skill | 研究准备 | 先检索成熟开源项目并映射八模块，确认后再选型 |

## 状态定义

`未开始 → 已设计 → 已手工验证 → 已稳定运行 → 可自动化 → 可复制交付`
