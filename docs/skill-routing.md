# 商业顾问：任务与Skill调用索引

公开整理：2026-10-05。这里维护任务分工与交接，不保存具体客户、素材、反馈或安装日志。总结构见[框架v2](business-consultant-framework-v2.md)，当前任务从使用者授权的本地任务记录进入；本仓库不附带个人 STATE。

维护分工：公开版 Skill 是方法指南，不包含私有素材、生产脚本或已登录浏览器环境，也不表示自动安装。

本索引只维护“选哪个入口、交接什么”；具体执行步骤以各Skill为准，业务结构以框架v2为准，任务事实与下一步留在STATE及关联私有记录。新增能力先检查已有Skill能否承接，避免同一流程多处各写一版。

## 1. 先找当前任务，不先跑完整流程

- 本轮用户明确的目标、范围与版本优先；没有改变的隐私、授权和暂停边界继续有效。
- 从STATE中定位**本任务**最新有效记录，再读其关联私有断点；不能把文件最后一条或最大画布版本号当作所有任务的当前状态。撤回与替代说明优先于被替代记录。
- 区分发起人的业务、客户自己的业务，以及我们向客户提供的服务。三者的画布、收入和验收不可串用。
- 框架解释用框架文档；商业判断用画布、访谈与实验方法；明确制作任务用对应Skill。不是每个问题都要调用Skill，也不需要先补全整个商业画布才能修改一个镜头。
- 只补本次交付真正缺少的输入。已有作品、原稿、透明母版或已确认布局可以直接进入中间环节。
- 若本任务身份或冲突版本确实无法确定，只问一个必要问题，不选择别的专项替代。

## 2. 六项独立Skill与一个名称别名

| 请求与交付目标 | 主入口 | 不应扩展成什么 |
|---|---|---|
| 了解某行业的内容类型、覆盖缺口、共性与反例 | [行业内容研究](../skills/industry-content-research/SKILL.md) | 不把少量账号汇总冒充行业结论；不无限研究后才允许制作 |
| 找账号、筛选列表、获取指定作品、整理已读内容 | [对标账号与内容获取](../skills/benchmark-content-discovery/SKILL.md) | 不自动升级为行业充分性研究或写稿 |
| 已有目标视频，需要获取媒体、核验画面声音或拆分镜 | [视频获取与分镜拆解](../skills/video-storyboard-analysis/SKILL.md) | 不重启找账号，不用ASR冒充完整观看 |
| 给分镜窗口问答找有来源的现成梗、列备选供选择 | [分镜对话找梗与替换审阅](../skills/storyboard-dialogue-memes/SKILL.md) | 默认不改编、不原创、不直接改工程 |
| 制作或修订公众号正文、配图与排版交付包 | [公众号图文制作](../skills/wechat-article-production/SKILL.md) | 不强制走视频链，不自动上传发布 |
| 人物抠像、接入HTML、调整大小位置、带原声视频导出 | [分镜剪辑](../skills/storyboard-editing/SKILL.md) | 不默认改稿、扩镜，不用预览代理代替母版 |

[AI账号发现](../skills/ai-account-discovery/SKILL.md)（`ai-account-discovery`）是第二项保留的原名入口，**仍属于商业顾问**；跳转至同一维护源，不重复计数，不搬迁历史素材。行业是任务参数，范围扩展不代表所有行业已实测。

Skill所在目录不等于已在每个环境自动加载；安装与验证状态查相应本地记录。Skill数量不表示能力成熟度或商业验证程度。平台提供的文档、表格、图片等工具是执行资源，不计入这六项项目自有Skill。

## 3. 重叠职责的分界

- **行业研究与对标获取：** 行业研究负责研究问题、样本覆盖、反例与暂收口判断；对标获取负责账号身份、来源、作品材料与读取记录。行业研究需要取材时复用获取流程和同一材料索引，不另建一套重复采集。仅整理几个指定账号时，停在材料支持的结论范围。
- **转写与视听分析：** 只要音频转写/已有材料整理时可留在对标获取；要画面、时间码、动作、转场或镜头判断时转到视频分析。媒体获取与转写可复用，不重复下载，证据不足的部分保留缺口。
- **原稿逻辑与找梗：** 顺序、叙事及参考映射用[原稿对照方法](single-content-storyboard-method.md)；窗口对白确需找梗才调用找梗Skill。用户允许二创时单独标记，不能冒充现成原句或计入原句数量。
- **逐镜制作与剪辑：** [逐镜制作方法](video-shot-production-workflow.md)负责镜头范围、画面设计、版本及验收；剪辑Skill负责人物接入与技术导出。已确认的背景和布局直接复用，不强制重新制作背景。
- **图文与视频：** 两条可独立完成的交付路径。跨形式复用需重新核对表达、授权与实际成品，不以视频完成替代图文验收。

## 4. 最小交接与证据边界

需要跨步骤时复用一份任务记录，至少能找到：任务/镜号、目标和允许范围、输入版本与来源、已确认项、输出路径、实际检查范围、缺口、下一步。不是每次新建表格；已有记录足够时直接引用。

后续步骤只有在输入齐备且执行范围获准时继续；“发现了可做的下一步”不等于已获执行授权。发布、联系客户、付费、安装或Git操作须遵守各自授权及项目隐私边界。

分别记录：文档存在、脚本检查通过、合成测试、真实素材试用、技术检查、用户验收、客户采用、实际支付、复购。它们不是一个可自动升级的总分；一种结果不能替代另一种。

## 5. 路由检查示例（合成请求，不是实测成果）

| 示例请求 | 应走的路径 | 不应发生 |
|---|---|---|
| “用AI账号发现，整理指定账号” | 原名 → 对标获取 | 说已废弃或移出商业顾问 |
| “只有这段视频，拆一下” | 视频分析 | 要求先研究整个行业 |
| “已抠好人物，按确认布局导出” | 剪辑的合成与验收 | 重抠像、重写脚本 |
| “把公众号第二段改短” | 公众号局部修订 | 重做所有配图或自动发布 |
| “给窗口问答找5个网上原句” | 找梗，核出处，缺额如实报告 | 改编凑数或暗改原工程 |
| “测试这个视频的声音同步” | 剪辑验收 | 进入Kimi对照实验 |
| “了解一个行业的内容生态” | 行业研究，需要时调用对标获取 | 只看一个账号就作行业结论 |
| “客户接受报价了” | 商业验证，记录承诺/报价状态 | 自动记为已付款 |
| “另一项任务刚更新，继续当前镜头” | 定位本镜头断点 | 执行STATE最后一条无关任务 |
| “原稿已确认，直接做指定背景” | 逐镜制作 | 强制找参考视频或加入笑话 |
