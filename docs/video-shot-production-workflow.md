# 逐镜拆解、制作与验收流程

## 原则

默认按本轮指定镜头或范围推进，不以整片自动生成为默认工作方式；用户明确要求多镜或整片时按授权范围组织制作与验收，不强制逐镜重新索取授权。拆解参考的表达机制，再用获准素材制作原创画面；不能因为参考画面可观看，就默认拥有复制发布权。

## 上游门槛：先确认叙事，再进入单镜

仅在本轮确需分析参考或调整原稿结构时使用[单条内容叙事与分镜对照](single-content-storyboard-method.md)：锁定最新原稿 → 原片逻辑分析 → 解释顺序调整 → 原片与原句逐拍映射 → 用户确认本轮制作范围。不固定旧稿镜数，不将表达节拍数当作独立背景数；同一主镜头的数字或图文变化可复用模板。

用户另改稿时，先判断影响哪些段落与镜头，不机械继承旧配音时长或将已废弃对白带回。当前只要求结构审阅时，停在审阅，不自动生成视频。已确认资产与用户自摄范围继续保留。

已有原稿、结构或资产已确认时直接复用；无参考片的原创任务不强制找对标。已抠像、已定布局的任务可直接进入[分镜剪辑Skill](../skills/storyboard-editing/SKILL.md)，不重做背景或叙事分析。

## 单镜闭环

1. **确认镜头**：记录镜号、台词、时长、参考画面和叙事作用；明确本轮修改与不修改的部分。
2. **核验素材**：区分真实行情/软件截图、合成数据、视觉演绎、真人与占位人物；缺少真实素材时明示缺口，不伪造来源。
3. **按缺口制作背景**：已有确认背景直接复用；需要新背景时，构图、色彩、运动与字幕安全区先定；按需使用占位人物预演，交付可替换的无人背景。
4. **单点迭代**：根据反馈只改指定变量，尽量保留已确认的时序、几何、构图和声音；新版本另存，不覆盖旧版。
5. **检查交付**：全帧解码、编码后抽帧、必要的运动时序检查；声音机器检测与人工听校分别记录。交付预览、背景、匹配字幕和音轨，复制后核验哈希。
6. **冻结确认版**：获得明确确认后，在私有记录中保存确认时间、源目录、交付路径、版本及哈希；以后不主动重做。
7. **进入下一镜**：先明确下一镜及仍缺的素材，再重复单镜闭环。最终确认版保留各镜确认记录，再核验整片拼接、声音衔接和真人合成；用户要求整片预览时可以先合成待审版，明确哪些镜头尚未确认，不称最终验收通过。

## 记录与版本管理

- 通用代码、流程与明确标注的合成示例可作为审查候选；用户反馈、个人台词、口播、成片及具体素材选择保留在已核验忽略的私有目录。
- 私有确认清单须包含：镜号、状态、素材边界、确认版、源文件、产物哈希、复核范围、未完成项、下一步。
- 默认不执行Git暂存、提交或推送。项目既有隐私清理未完成时不得用常规提交发布绕过审查；另获明确授权且通过隐私检查后，才考虑白名单操作，不夹带其他任务改动。
- 本地提交不等于远端推送。同步、公开发布、历史重写分别确认，不以仓库私有代替隐私审查。
- 恢复工作时先读最新私有确认清单和任务状态，不能依据旧日志重做已确认版本，也不能把部分镜头验收写成全片完成。
- 保存续接说明不等于已创建后台任务；用户明确要求定时或提醒时另按调度工具规则处理，不声称仅写文件就会自动执行。
