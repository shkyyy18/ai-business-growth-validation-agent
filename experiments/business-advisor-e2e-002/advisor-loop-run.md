# 商业顾问整套流程：公开研究输入版跑通记录

日期：2026-09-14。运行对象：**公开研究输入，不是客户案例**。

这份记录把用户描述的顾问方法串起来，但不把缺失的客户资料伪造成结果。它的用途是确认：拿到真实公开内容后，下一步如何从研究进入诊断、借鉴、产品、直播和复盘；每一段的真实输入、产出和停点均可追溯。

## 0. 启动判断：现在能判断什么，不能判断什么

可判断：本项目已经取得两批、11个公开聚合页的真实快照；合并后135个稳定公开身份、172条去重作品、81条有平台AI文稿字段、62条已阅读文稿，其中42个身份至少有一条阅读记录。阅读内容覆盖职业咨询、IP/知识付费、口才训练、家庭教育/记忆训练质疑、办公课交付和相邻内容。来源、身份、作品边界和缺失值可重放。

不可判断：这些身份不是客户；样本不是全行业标准；推荐流不是连续主页；没有原视频、音轨、留存曲线、商城订单、直播录屏、利润、客户历史内容或实际交付。因此目前只能完成“行业研究输入和顾问交接”这一段，不能给客户下问题诊断或宣布商业闭环。

## 1. 客户前置诊断：不拿行业样本替客户回答

收到客户后按这个顺序取证：

1. 看历史内容：同一账号取一段有代表性的高数据、常态、低数据/有研究价值内容，并记录发布时间、形式、播放/点赞/评论/转发/收藏、投流未知项；不预设固定条数。
2. 问直播情况：直播场次、同一窗口的曝光/进入、观看、停留、成交、GMV、投流、退款、成本和产品履约；先冻结平台字段定义，再算进入率、转化率、千次观看成交、GMV ROAS和利润ROI。
3. 判断问题分叉：方法论缺失、抖音表达/制作不适配、内容选题/观点本身、产品/承接/交付问题。用历史内容与研究库对照，不能只用前五秒或点赞单因归因。
4. 判断客户在行业的位置：以可比窗口和内容/产品证据写“暂定相对位置”，不把粉赞比公式、头腰尾阈值或作者收入口号当规则。
5. 客户确认问题、基线、资源、验收后，才进入改写和直播测试。

**停点**：客户未提供资料或授权时，停在“研究交接”，不模拟客户痛点、不替客户选择产品、不生成承诺性话术。

## 2. 行业研究与内容库：本批已经实际交付的中间件

- 研究索引：`research/m1-channel-discovery-2026-09-14/discovery-index.json`、`research/m1-professional-2026-09-14/discovery-index.json`。
- 合并库：`experiments/business-advisor-e2e-002/public-corpus.json`。
- 阅读笔记：专业扩展批次37条；前两批60条，加既有发现池的2条直播复盘教学补充阅读，共62条（作品不新增）。每条绑定来源快照、JSON路径和平台文稿指纹。
- 归组卡：`content-families.json`。它把高度相近的口才五点、职业咨询、办公课购后支持和记忆训练质疑作为研究家族，不当成独立观点数量。
- 研究范围动态结论：职业咨询/训练课程分支已有初步材料；家庭教育、直播承接、商城成交和连续账号流仍薄弱，下一批优先补这些缺口，而不是机械凑固定账号数。

### 研究结果如何进入“网感”

网感不由几个样本自动产生。本批的可用替代物是：阅读记录→结构卡→家族去重→反例→不能迁移理由。后续每次改写前先从库里选择一组同类、一个常态对照和一个反例，再由行业专家决定是否值得借鉴；AI只负责扩大阅读、归属、检索、对照和保留证据。

## 3. 内容拆解与借鉴：只抽结构，不复制事实和承诺

当前可给客户展示的拆解结论（不是客户稿）：

- **职业咨询结构**：具体人群/困扰 → 重新解释其优势或冲突 → 个案判断 → 岗位/行动建议 → 课程或咨询入口。可借鉴的是问题具体化和判断过程；不能借鉴未经证明的涨薪、效果或性格决定论。
- **口才训练结构**：点名场景（汇报/上台/陌生人） → 先解决“敢说” → 分阶段练习任务 → 资料/训练营/工具承接。可借鉴任务分层和承接位置；不能借鉴“几天必变好”、群体数字、心理/人格绝对归因。
- **课程交付结构**：购课问题 → 手机/电脑入口 → 登录或兑换 → 异常分支 → 学习/礼包 → 私信支持。它不是爆款脚本，却是产品体验素材，值得纳入内容库。

任何复刻稿必须另列：原素材ID、保留结构、客户自己的事实/专业观点、删除内容、风险、人工核验人。没有客户原观点和产品边界，保持拆解卡，不进入拍摄稿。

## 4. 产品设计：提出候选，让客户专家做决策

本批公开材料支持提出三个**候选形态**，不支持替客户拍板：

A. **诊断+内容库+单轮改写**：先研究其行业和账号，再判断一个问题，交付可回溯样本、结构卡、改写稿和发布后数据表。适合需要先厘清问题的客户。

B. **课程/服务产品+购后支持优化**：围绕用户购买、兑换、观看、作业和问题咨询画交付路径，补异常说明和服务边界。适合内容数据尚可但交付/复购摩擦明显的客户。

C. **直播小实验+复盘**：客户确定产品和库存/履约边界后，选一个内容入口与一个直播承接假设，冻结窗口和指标，小范围测试，再决定是否扩展。不能承诺ROI。

公开样本中的课程、训练营、工具或礼包，只能作为候选形态线索；客户是行业专家，应确认产品是否真实、可交付、合规、值得卖。价格、利润、复购和供应链仍需客户证据。

## 5. 热点与改写：没有热点就不硬接

当前没有把任何未核实事件包装成热点，也没有把行业无关热点强行接入。本项目已确认的规则是：热点只是让内容库中的某个观点获得再次讨论的入口；行业无关不采用，切实负面热点先核实并慎用。实际执行时补一张事件卡：来源、日期、事实核验、与原观点的关联、风险、保留/改写/不采用决定。没有可核对热点和客户原内容，停在规则层，不造事件、不写指向他人的负面稿。

## 6. 直播话术与测试：摘结构，不盗取或承诺

客户授权直播录屏/直播文字后，先把“开场、问题诊断、产品说明、异议、交付、CTA”分段，摘取结构和客户自己的产品事实，改写成可人工核对的话术。当前公开文稿只能提供课程承接和购后支持的语言线索，不能当某直播间完整话术，更不能直接摘抄、复制或发布。

测试单只改变一个主要变量，例如“问题具体化入口”或“购后支持说明”；记录同一窗口的曝光、进入事件、观看UV、观看时长、买家UV、GMV、广告归因GMV、广告花费、实际利润和总成本。严格区分：进入事件/PV、进入UV、实时流入曲线、GMV ROAS、利润ROI。分母缺失或为0输出未知/null，不填0。

## 7. 本轮验收结论

- **研究链路：部分跑通。** 真实公开页面→快照→安全解析→主/推荐归属→去重→阅读→家族归组→合并库→查询，已有可重复测试。
- **顾问诊断：方法和输入接口跑通，客户判断未跑通。** 因为没有当前客户资料，不能判断内容问题属于哪一类。
- **内容借鉴：结构拆解跑通，客户复刻未跑通。** 缺客户原内容、产品事实、授权和发布测试。
- **产品建议：候选生成跑通，客户决策和交付未跑通。** 公开商品线索不等于客户产品或成交。
- **直播复盘：计算器和指标口径跑通，真实直播未跑通。** 没有同窗客户导出和执行结果。
- **商业闭环：未验证。** 无实际报价、支付、客户采用、验收、复购和成本结果。

这不是保守措辞，而是本次跑通的真实边界：不能用研究样本、代码绿灯或文稿数量替客户的支付和经营结果。
