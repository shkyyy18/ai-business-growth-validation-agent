## H-001 已提取：古筝线上课程商业化全案

### 已确认事实（来自发起人本次叙述）

- 客户类型：古筝专业老师/古筝培训业务。
- 客户目标：跑通线上新媒体链路，通过线上直播卖古筝课程。
- 当时状态：内容创作、直播运营、产品制作与上架、产品交付等环节都不通畅，需要重新跑一遍。
- 内容与获客：寻找对标账号和对标内容，拍摄、剪辑内容，通过内容为直播引流。
- 直播运营：实时回复直播间潜在用户问题；产品上架；逼单；直播节奏把握；观察流量；实时投流介入。
- 产品开发：古筝歌曲授权开发；单月古筝培训课程开发；跨年古筝培训课程开发；竞品直播间产品研究；竞品内容研究；竞品数据分析。
- 自有业务复盘：对自身内容、直播和业务数据进行分析复盘。
- 私域与交付：私域搭建；社群建立与互动；群内互动；课后作业批改；课程表设置；课程具体传达。

### 当前能确认的能力

- 能把专业能力拆成线上课程商业化的多个业务环节；
- 能识别并协调内容、直播、产品、投流、私域和交付之间的依赖关系；
- 能将竞品研究、内容执行、直播运营、产品开发和课后交付放进同一条经营链路；
- 能进行业务数据观察和复盘，而不是只关注内容发布；
- 能在多个环节同时不成熟的情况下，推动系统从零开始运行。

### 尚未确认的事实

- 当时的具体周期、团队人数和发起人的独立贡献比例；
- 内容、直播、投流、课程销售和复购的具体数据；
- 哪个环节造成的损失最大；
- 哪个环节最频繁、最耗时、最适合标准化；
- 客户最终是否持续执行、续费或复购；
- 当时的收费方式、项目利润和客户验收标准。

### 初步拆分：AI 可以辅助的节点

| 业务环节 | AI 可辅助内容 | 仍需人工判断 |
|---|---|---|
| 竞品与市场研究 | 账号、内容、产品和直播资料的采集、归类、对比、摘要 | 选择真正可借鉴的竞品，判断是否适合自身业务 |
| 内容获客 | 从专业素材提炼选题、脚本、标题和拍摄清单 | 选题取舍、专业真实性、镜头表现、最终发布 |
| 直播运营 | 直播问题分类、回复草稿、产品信息调用、节奏提醒 | 实时判断、承诺边界、逼单时机、投流决策 |
| 产品开发 | 课程结构、竞品对照、产品组合、上架资料草稿 | 授权合规、课程承诺、定价、交付可行性 |
| 私域运营 | 群公告、互动主题、作业提醒、问题分类、社群复盘 | 客户关系、个别学员判断、冲突处理、教学质量 |
| 课程交付 | 课程表、作业收集、批改初稿、学习进度摘要 | 教学评价、纠错、个性化指导、最终反馈 |
| 数据复盘 | 内容、直播、产品、社群和作业数据的汇总与异常提示 | 归因、优先级和下一轮资源分配 |

### 当前判断

H-001 证明的第一层价值不是“帮老师生成内容”，而是“帮专业老师建立并运行线上课程商业化闭环”。但全链路过宽，不能直接作为第一个 Agent 的交付边界。需要继续确认：当时哪个单一环节最痛、最重复、最容易因资料结构化而提效，并从该环节切出第一版。

## H-001 追加：发起人的明确优先级

发起人希望将以下能力纳入对外 Agent：

1. 对标账号寻找、对标内容寻找、选题、内容编写和剪辑；
2. 直播间评论区 AI 回复与意向识别；
3. 研究热卖课程产品构成，并结合客户自身特点创作课程产品；
4. 私域 SOP、标准化语言和 QA 常见问题整理；
5. 内容、直播、产品和私域数据分析复盘。

当前最急迫的是内容创作和剪辑。因此第一版从 M1 内容研究与生产开始，其余能力作为同一 Agent 的后续模块，不拆成五个互相独立的产品。

### 新的首版判断

首版最小结果不是“生成一段文案”，而是：

> 从一个专业老师的业务和公开对标资料出发，在一个工作周期内产出一组有依据的选题、可拍脚本和一条可执行的剪辑方案，并让至少一条内容真正进入拍摄、剪辑或发布。

### 需要继续确认

- 最常用平台和视频形态；
- 客户内容发布频率和当前素材来源；
- 用户希望 AI 直接完成到什么剪辑深度；
- 现有剪辑工具和素材文件格式；
- 内容主要引流直播、私信、加群还是直接卖课；
- 对标账号的来源、可公开程度和研究方式。
