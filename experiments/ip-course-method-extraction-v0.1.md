# 个人 IP 课程：方法论与 AI 任务提取 v0.1

更新日期：2026-09-12
状态：主案例拆解稿；不代表重新销售、重做或重新上线这门历史课程。

## 一、案例用途

这份案例用来提取发起人已经做过、讲过和交付过的工作方法。它要回答的是：

> 发起人过去到底用什么判断，帮助别人把专业能力变成个人 IP 和业务结果？其中哪些工作可以由 AI 辅助，哪些工作必须保留人工判断？

它不用于：

- 重新设计历史课程；
- 确定现在的课程价格或销售计划；
- 证明历史客户今天仍愿意购买；
- 直接把“个人 IP 课程”确定为未来商业产品。

## 二、为什么把个人 IP 课作为主案例

古筝、英语、钢琴、产康和财税等项目，是方法在不同专业领域中的应用案例。个人 IP 课程则更接近发起人自己的方法论总集，能够观察：

- 发起人如何定义个人 IP 的业务目标；
- 如何把客户的专业能力组织成定位、内容、直播、产品和交付；
- 哪些判断可以反复迁移到不同专业领域；
- 哪些内容只是当时的行业经验，不能直接抽象为通用方法；
- 哪些环节可能适合 AI 辅助，形成可重复的工作流。

## 三、目前已确认的事实

以下内容来自发起人的自述，属于已确认背景：

- 发起人自己做过个人 IP；
- 曾通过教授个人 IP 方法销售课程；
- 曾为客户提供个人 IP 全案孵化；
- 合作对象包括古筝、英语、钢琴、产康、财税等专业老师或专业服务者；
- 历史交付涉及内容、直播、课程产品、私域和交付等多个业务环节；
- 发起人现在希望从这些历史经验中提取 AI 可以帮助别人完成的任务，而不是直接复刻历史项目。

## 四、当前不能擅自补写的内容

以下信息还没有从课程原始资料或发起人的逐模块说明中确认：

- 课程的真实模块和先后顺序；
- 每个模块要解决的具体客户结果；
- 课程中的具体工具、表格、模板和作业；
- 哪些内容是公开课，哪些内容属于高阶交付或全案孵化；
- 学员完成课程后的验收结果；
- 历史课程的具体价格、成交量、交付周期和利润；
- 哪些方法在不同客户项目中反复有效；
- 哪些结果主要依赖发起人的现场判断、资源和执行能力。

## 五、拆解方法

每个课程模块都按以下链路提取，不把“讲过一个概念”直接等同于“形成了可交付能力”：

```text
模块目标
→ 学员/客户当时的具体问题
→ 所需输入资料
→ 发起人的关键判断
→ 交付物或行动
→ 客户是否执行
→ 执行后的可观察变化
→ AI 可以辅助的步骤
→ 必须由人工负责的步骤
```

## 六、待从课程中确认的能力模块

下面只是拆解目录，不是对历史课程模块的事实断言：

| 待确认模块 | 要查明的问题 | 可能的 AI 辅助方向 |
|---|---|---|
| 业务目标与定位 | 个人 IP 最终服务什么业务结果，面向谁 | 资料整理、定位选项对照、问题澄清 |
| 专业能力提炼 | 如何把客户经历、专业知识和案例提炼成可表达资产 | 访谈转写、能力标签、案例结构化 |
| IP 主题与内容支柱 | 如何决定长期讲什么、为谁讲、哪些问题反复讲 | 主题聚类、问题库、内容支柱候选 |
| 对标与市场研究 | 如何寻找对标账号、内容和产品，并判断可迁移性 | 公开资料整理、结构拆解、差异对照 |
| 选题与脚本 | 如何把专业判断变成用户听得懂的内容 | 选题池、脚本初稿、证据和边界提示 |
| 拍摄与剪辑 | 如何让内容进入实际拍摄、剪辑和发布 | 转写、时间轴、字幕重点和剪辑清单 |
| 直播与成交 | 内容如何自然承接直播，直播如何完成答疑和成交 | 评论分类、FAQ 检索、异议整理和复盘 |
| 产品设计 | 如何把专业能力做成课程或服务 | 竞品结构对照、产品大纲和交付清单 |
| 私域与交付 | 如何把成交后的服务和课程交付稳定下来 | SOP、通知、QA、作业和进度摘要 |
| 数据复盘 | 如何决定下一轮先改什么 | 数据整理、异常发现和复盘草稿 |

只有在课程原始内容或发起人具体回忆中出现，某个模块才会被标记为“已确认”。

## 七、初步能力假设

这些是待课程材料验证的工作假设：

1. 发起人的核心能力可能不是单点内容生产，而是把专业能力组织成一条“定位—内容—直播—产品—交付”的业务链路。
2. 发起人的可迁移能力可能是从复杂经历和业务资料中提取主线，并把主线转换为客户能够执行的内容与动作。
3. AI 的首要价值可能是降低研究、整理、改写、记录和复盘成本，而不是替代发起人的业务判断。
4. 真正可能形成商业价值的交付，不一定是一个完整的“课程增长 Agent”，也可能是某个高频窄任务，或人工 + AI 的诊断/陪跑服务。
5. 这些假设必须经过课程方法提取、历史项目对照和至少一次真实任务演练后，才可以进入商业画布。
