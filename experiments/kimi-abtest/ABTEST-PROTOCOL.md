# Codex 独立 vs Codex + Kimi K3 对照测试协议

- 建立日期：2026-09-12
- 测试项目：AI 商业增长验证 Agent
- 测试目的：比较 Codex 独立运行与 Codex 规划 + Kimi K3 执行，在本项目 AI 工作环节上的完成度、稳定性、一致性和性价比。
- 当前窗口说明：若 Kimi 于 2026-09-15 到期，则从 2026-09-12 起按首尾计算最多 4 个测试日；不是完整 5 个自然日。

## 一、核心原则

1. 两条路径必须使用同一份输入资料和同一个任务目标。
2. Codex 独立路径与 Kimi 执行路径不得读取对方的输出。
3. 不直接比较文字是否相同，比较事实、判断、任务完成、边界遵守和可执行性。
4. 测试期间不直接修改项目核心事实/决策文件；先在本目录产生隔离产出。
5. 只有通过复核的结果，才允许回写正式项目文件。
6. Kimi 的计划必须由 Codex 生成，但 Kimi 的执行结果必须单独评分。

## 二、每轮目录

```text
experiments/kimi-abtest/day-N/
├─ input-manifest.md       # 本轮输入文件和任务约束
├─ codex-direct.md         # Codex 独立路径产出
├─ kimi-plan.md            # Codex 为 Kimi 生成的执行计划
├─ kimi-output.md          # Kimi 执行产出
├─ review.md                # 结果比较和复核
└─ metrics.md               # 时间、返工、错误、成本记录
```

## 三、每轮执行步骤

### A. 冻结输入

记录任务开始时间、相关文件路径、Git 状态和禁止修改范围。两条路径都只以该清单为事实来源。

### B. Codex 独立路径

让 Codex 在不调用 Kimi 的情况下完成任务。产出只能写入 `codex-direct.md`，不能修改正式项目文件。

### C. Codex 交接路径

让 Codex 根据同一份 `input-manifest.md` 生成 `kimi-plan.md`。计划必须包含目标、事实、假设、允许修改范围、禁止事项、步骤、验收标准和异常处理。

### D. Kimi 执行路径

Kimi 只读取项目规则、`input-manifest.md` 和 `kimi-plan.md`，将产出写入 `kimi-output.md`。如计划不清楚或需要越界，必须暂停并报告。

### E. 盲式初评

先分别记录两份产出的事实准确性、完整性和规则遵守情况，再比较共同点和差异，避免先入为主。

### F. 复核和记录

记录是否需要返工、是否发现越权、是否出现虚构、是否可以直接进入正式项目，以及哪条路径更适合该类任务。

## 四、评分表（100 分）

- 事实与项目上下文准确性：25 分
- 遵守 AGENTS.md 和现有决策：20 分
- 任务目标完成度：20 分
- 可执行性和具体程度：15 分
- 产出结构、可复用性和文件质量：10 分
- 稳定性、耗时和恢复成本：10 分

另行记录：

- 交接损耗：0-5 分（越低越好）
- 未授权修改文件数
- 虚构事实/证据条数
- 返工轮数
- 从开始到可接受产出的分钟数
- 中断后是否可恢复

## 五、测试任务梯度

### Day 1：低难度

商业顾问启动状态汇报：使命、阶段、决策、商业假设、画布状态、未完成下一步。

### Day 2：中难度

基于真实项目资料生成个人商业画布草案，严格区分事实、假设、待验证项，不改变正式文件。

### Day 3：中高难度

比较 A/B/C 三个候选方向，设计 7 天客户问题验证实验，包含目标客户、问题脚本、成功阈值、失败判定和记录字段。

### Day 4：高难度

模拟收到一组新的创始人约束后，判断是否可以进入客户验证，更新一份隔离的状态建议；必须识别冲突、缺口和不能提前下结论的事项。

若到期日确实为 2026-09-15，Day 4 作为收官测试；若 Kimi 实际可用到 2026-09-16，再补 Day 5：长任务恢复和修订测试。

## 六、最终决策规则

- 不是总分高就自动胜出；核心商业判断和正式决策文件仍由 Codex 或用户批准。
- 若 Codex + Kimi 总分高至少 5 分，且交接损耗不超过 10%、无严重越权，则推荐组合。
- 若组合只在低风险文档任务上领先，而在方向判断上明显下降，则采用分层协作，不让 Kimi 独立决策。
- 若 Kimi 未能稳定完成中高难度任务，或返工成本抵消其稳定性收益，则不续费高档套餐。

## 七、预算记录

1000 元预算用两种方式模拟：

1. Codex 独立：1000 元全部计入 Codex 中转站调用预算，记录实际调用消耗和有效产出数。
2. Codex + Kimi：699 元固定计入 Kimi K3，剩余 301 元计入 Codex 中转调用预算；若实际套餐价格或到期规则不同，以用户实际账单为准。

性价比采用：

```text
有效完成分 ÷ 实际成本
```

同时记录每个可接受产出的人工复核和返工时间，避免只比较模型价格。

## 2026-09-12 实施纠正（优先于上文冲突条款）

1. 本次是实际工作流配对试跑，不是盲评；当前Codex兼任A作者、B计划作者、评审，且双方历史上下文不等价。不能据此推出裸模型排名。
2. 冻结必须复制实际输入并记录SHA256，不能只列路径。两边可读同一批冻结源文件；B额外读计划，不能读A答案。目录分离不等于操作系统级沙箱，工具记录也需检查。
3. 每轮执行前固定细化评分项，保留首轮原文与首次评分；修订另存。Day 1使用day-1/scoring-rubric.md的90分表，运行10分因A数据不足记N/A，不填造100分总分。
4. 后续任务跟随用户当天真实工作，不为凑上述梯度跳过项目阶段。复杂度按实际输入冲突、推断和约束数量注明；模拟任务单独标记，不能冒充业务证据。
5. 撤销上文“高5分/交接损耗10%即可推荐”的未经验证阈值。续费要看代表性任务是否通过、硬失败、用户接受、返工和真实成本；证据不足就保持未定。不预设哪种架构更可靠，二者都可设计检查点恢复。
6. 替代单一“分数÷成本”：主要统计验收任务数、首轮通过率、修订后通过率、每个验收任务的现金成本和用户干预分钟；不同难度分别报告，避免做大量简单任务虚增性价比。
7. 成本分两本账：剩余已付套餐期间的新增现金支出；续费后的完整月成本。组合成本必须含Kimi套餐、Codex写计划/复核/返工调用，不漏掉规划开销。不能把未消耗的预算当实际支出。
8. 按用户提供的699元报价做情景：1000元总预算中Kimi固定699元，Codex最多301元。0.4倍率不能单独换算任务成本，还需实际基础计费、缓存、token和账单。月度是否可行取决于代表性任务量与复核消耗，当前不下结论。
9. 没有自动日程承诺。用户每日继续会话或提供更新后再执行。若实际2026-09-15到期，2026-09-12到15仅跨3天、含首尾最多4个日期，具体最后可用时刻看账户。
