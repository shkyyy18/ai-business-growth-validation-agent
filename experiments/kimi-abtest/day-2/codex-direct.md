# Day 2 Codex 独立路径首轮产出

## 1. 当前使命、阶段和唯一下一步

**事实（来源：`business/STATE.md`、`agent/AGENT.md`）：** AI商业顾问的使命是用真实客户问题验证“AI 如何帮助别人并形成收入”，再把已验证的人工 + AI 交付标准化、自动化和产品化。新媒体是获客、建立信任和研究市场的渠道；AI 是研究、交付、复盘和未来复制的增强能力。当前处于阶段 1：重建个人能力与商业假设，已完成项目审计，进入创始人经验提取和熟人客户试用验证。

当前唯一主动作是：用户按记忆口述个人 IP 课程从开始到结束的大致模块，每个模块说明解决的问题、学员动作和希望结果；再拆成模块目标、客户问题、输入、关键判断、交付物、执行结果、AI 可介入步骤、人工责任和待验证假设。M1-001 是能力验证案例，不表示重新销售历史课程。

## 2. 个人目标、资源和约束

| 类型 | 当前记录 | 证据状态 |
|---|---|---|
| 目标 | 希望未来三个月收入尽可能高，没有设上限 | 用户自述；最低目标、冲刺目标和时间边界待确认 |

## 3. 个人商业画布草案

这是在已有 `candidate-canvas-v0.2-p1.md` 基础上的工作版，不是最终定位。每一项均区分当前记录、假设和验证动作。

| 画布要素 | 当前事实/记录 | 当前假设 | 待验证 |
|---|---|---|---|
| 客户细分 | 历史上接触过专业人士、老师、顾问、培训师和本地生活商户 | 首轮可能聚焦已有课程/服务、持续发布内容但有效咨询或预约不稳定的专业人士或小机构 | 具体身份、问题急迫度、可触达性、是否愿意授权资料和付费 |
| 客户任务/问题 | P1 将任务限定为分析近 10 条内容、3—5 条咨询和预约结果，寻找内容到有效咨询/预约的断点；P2 是咨询后的分层、跟进和预约流程 | 痛点可能在内容承诺、入口、资格筛选、回复、跟进或预约连接，而不只是内容生产 | 至少 3 次具体事件访谈、1 次授权资料诊断；确认问题频率、损失和当前替代方案 |
| 价值主张 | 现有画布提出：用真实资料做人工 + AI 诊断，缩短从模糊感觉到下一步行动的时间 | 找出一个优先断点并设计一周可执行、可观察的改进实验，可能比泛内容服务更容易验证 | 客户是否把该结果视为有价值，是否执行，是否愿意继续或付费 |
| 解决方案/交付物 | 候选交付包括事实/推断/未知摘要、链路图、断点假设、指标定义、回复/跟进草稿、7 天记录表和复盘 | 先做一次窄范围诊断或能力样例，再决定陪跑、课程、模板、Agent 或软件 | 实际耗时、修改次数、客户采用、至少一个行为指标变化；当前不承诺涨粉或成交额 |
| 渠道 | 内容公开展示问题分析和方法；老客户/同行转介绍；少量定向访谈 | 内容 + 熟人验证符合用户偏好，能够建立信任并筛选线索 | 哪个渠道能触达具体人，线索质量、沟通成本和授权率 |
| 客户关系 | 先访谈，再一次性诊断；结果成立后再考虑短周期陪跑/实施 | 低承诺首单和结果导向关系可降低双方风险 | 客户是否愿意提供脱敏资料、执行 7 天动作和反馈；沟通边界与服务周期 |
| 收入 | 现有画布写有诊断试单 999—1999 元，后续实施另行报价 | 可能存在小额诊断的付费锚点 | 这只是实验锚点，需通过正式报价、实际支付和交付复盘验证；未发生付款 |
| 关键资源 | 个人销售/增长/新媒体/IP 孵化经验，AI 结构化和工作流能力，历史案例，内容渠道 | 能将业务判断与 AI 提效结合，形成可复现交付 | 可公开案例归属、授权、可脱敏样例、现有联系人和工具成本 |
| 关键活动 | 访谈、资料诊断、人工复核、实验设计、执行反馈、复盘和内容表达 | 以人工先行、AI 增强方式更适合当前证据量和风险 | 一次完整任务的实际时间、重复性、客户完成度和可标准化程度 |
| 关键合作 | 客户提供脱敏资料并执行记录；必要时与内容、投放或技术人员协作 | 客户的资料和执行是交付闭环的一部分，不能由顾问单独保证结果 | 客户能否稳定提供资料和执行；是否确有外部协作者需求 |
| 成本 | 访谈和诊断时间、内容制作、工具/API、沟通和复盘成本 | 早期主要成本可能是本人时间和复核，而不是先开发软件 | 实际每单调用费、人工分钟、返工次数、获客成本和客户配合成本 |
| 关键指标 | 可观察指标包括有效咨询数、预约率、跟进完成率、客户执行情况；过程指标包括交付耗时、修改次数 | 7 天内至少能观察一个行为指标，才有继续验证价值 | 先取得基线和定义口径；不能把播放量直接当业务结果，也不能预设提升幅度 |
| 风险/不能下的结论 | 客户可能真正需要代运营或投放；无基线或不执行；根因可能是产品、流量或履约；诊断难归因 | 一个窄交付可能逐步收敛成服务，但尚无证据选择最终形态 | 记录失败原因、未完成动作、归因限制；暂不能判断市场规模、定价、收入上限或长期可复制性 |

## 4. M1、P1 与候选方向的关系

- **M1-001**：当前已确定的能力验证案例。主样本是用户自己的历史个人 IP 课程，用于提取方法论；古筝、英语、钢琴、产康、财税项目是应用旁证。下一步是口述模块，不是补写正式课件或重卖课程。
- **P1**：候选的首个客户任务假设，即“内容到有效咨询/预约诊断”。它与内容、咨询和转化链路有关，尚未完成客户验证。
- **A/B/C**：候选画布方向中，A 偏专业人士/老师的 AI 个人 IP 获客陪跑，B 偏本地生活商户的内容—线索—到店优化，C 偏小型 IP/运营团队的交付提效。当前不把排序当最终选择，也不能用宽泛标签代替具体任务。

因此当前工作不是在 M1、P1 或 A/B/C 中立即选产品，而是先从个人 IP 课程提取真实方法和人工判断边界，再用一个授权的客户任务检验是否能交付可观察结果。

## 5. 人工 + AI 最小交付流程

1. **定义问题和授权**：本人确认客户身份、最近一次具体事件、目标、资料范围和脱敏方式；客户授权使用资料。
2. **整理输入**：AI 可转录、归类、去重和建立事实/推断/未知表；本人检查上下文、敏感信息和事实准确性。
3. **形成诊断草稿**：AI 可对内容、咨询、预约和跟进字段做结构化比较，提出候选断点和指标；本人选择唯一优先断点，判断是否有足够基线，拒绝无证据归因。
4. **设计实验**：AI 可生成 7 天记录表、动作清单和回复草稿；本人确定业务语气、资格标准、动作范围和风险边界。
5. **执行与复盘**：客户执行并记录；本人解释结果、处理例外和决定继续/调整/停止；AI 可汇总记录和生成复盘草稿。

最小输出是“一页事实/推断/未知摘要 + 一个优先断点 + 一份 7 天动作和指标记录表 + 一次复盘约定”。不能承诺固定涨粉、收入、成交额、自动代运营或无需客户配合的结果。

## 6. 当前最小验证动作

**第一步（当前主线）：** 用户口述个人 IP 课程模块。对每个模块只收集：解决的问题、学员要做什么、希望得到什么结果。随后记录输入、判断、交付物、执行结果、AI 可介入步骤、人工责任和待验证假设。不要要求旧课件、价格或销售数据，不把历史学员结果补成事实。

**第二步（能力核验）：** 从口述中选一个模块，形成一张能力卡：输入是否具体、本人判断是否不可替代、AI 草稿能否被复核、输出是否可展示、耗时和人工修改是否可记录。再与 P1 或其他具体客户任务对照，判断“可演示”“需样例验证”或“不匹配”。

**后续客户验证（尚未开始）：** 找到一个经同意的专业人士样本，记录最近一次内容/咨询/预约事件，取得脱敏资料和基线，完成一次诊断并约定 7 天执行。没有这些证据前，不宣布 P1 成立。

成功信号：模块口述能形成清晰、可复核的流程；能力卡的输入、输出、人工责任和耗时可重复记录；客户能讲出具体事件并愿意提供资料、执行和反馈。失败信号：只能给泛泛方法；关键判断依赖未提供的资料；客户真实需求是代运营/投放；客户不执行或无法提供基线；交付耗时和修改成本超过可接受范围。

建议记录字段：日期、样本/客户编号、任务、输入范围、授权状态、事实、推断、未知、AI 操作、本人操作、人工修改、开始/结束时间、交付物、客户执行、指标基线、结果、反馈、下一步和不能下的结论。
