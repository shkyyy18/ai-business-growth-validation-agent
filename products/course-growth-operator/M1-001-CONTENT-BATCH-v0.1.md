## 一、业务卡

- 案例中的课程：帮助已经有课程或服务的老师、顾问、培训师利用抖音打造个人 IP 的课程；1999 元为历史案例价格，仅作背景
- 平台：抖音
- 形式：1—5 分钟口播
- 首轮受众：已经有课程或服务的老师、顾问、培训师；他们有专业能力和交付内容，但不会把内容、直播和课程连接起来
- 内容目标：让目标用户独立获得一个清晰判断，并逐步形成对创作者专业能力和长期主题的认知
- 直播关系：直播是后续的深度信任、答疑和成交场景；本批内容不强制为直播预告或导流
- 内容阶段：先验证目标人群是否认可问题和表达方式，再观察关注、持续观看及自然进入直播的行为

## 五、优先内容 brief：T01

### 标题候选

1. 已经有课程或服务，为什么还是做不好个人 IP？
2. 很多有课程的老师做不起来个人 IP，不是因为没内容
3. 有课程、有经验，为什么还是讲不清自己？

### 一句话观点

有课程或服务只是起点。用户能不能听懂、记住并认为与你有关，取决于你是否把课程价值转成一个具体人的具体问题。

### 内容结构

1. 开头提出反常识问题；
2. 解释“已有课程/服务”和“公众表达”不是一回事；
3. 给出三个表现：只介绍自己、一次讲太多、没有明确服务对象；
4. 给出一个判断标准：用户听完是否知道你帮谁解决什么问题；
5. 用一个脱敏历史经验补充真实感；
6. 以关注/收藏/继续观看同类主题作为自然结束。

### 口播脚本初稿

很多已经有课程或服务的老师、顾问，反而更容易做不好个人 IP。

不是因为他没有东西，而是因为他习惯用“我的课程有什么”来组织内容，用户却是用“这和我有什么关系、我为什么现在要听”来判断要不要继续听。

第一个常见问题，是一上来介绍课程模块、资历和经历，却没有说清楚自己长期帮助哪一类人解决什么问题。

第二个问题，是担心讲少了显得不专业，于是一条视频里同时放观点、方法、案例和结论。结果信息很多，用户却记不住你到底讲了什么。

第三个问题，是把个人 IP 理解成单纯包装自己。真正稳定的个人 IP，不是把课程目录拆成很多条，也不是每天换一个热点，而是持续回答一类人的一类问题，让别人逐渐知道你为什么值得关注。

你可以检查一下：用户看完这条内容，能不能用一句话说出你帮助谁解决什么问题？如果不能，问题可能不在拍摄和剪辑，而在内容还没有形成清晰的价值主线。

后面我会继续拆解，老师、顾问和培训师怎样把自己的知识变成普通人听得懂、愿意持续看的内容。

### 拍摄要求

- 预计成片：70—100 秒；
- 采用正面口播，三个问题分别做轻微停顿；
- 开头直接进入问题，不使用“大家好我是……”的长铺垫；
- 每个问题出现时，在画面上显示一个短标题；
- 结尾不强行预告直播，不直接销售 1999 元课程；
- 如果账号当时正在直播，才根据实际情况补一句自然的直播提示。

### 剪辑方案（没有原视频时间码时的预案）

| 成片段落 | 处理建议 | 目的 |
|---|---|---|
| 00:00—00:04 | 保留最有冲突的问题，删除寒暄 | 让用户快速判断是否与自己有关 |
| 00:04—00:15 | 保留“不是不专业，是组织方式不同” | 形成核心转折 |
| 00:15—00:35 | 问题一单独成段，字幕只保留关键词 | 降低信息密度 |
| 00:35—00:55 | 问题二配合停顿或轻微切镜 | 让观点有节奏 |
| 00:55—01:15 | 问题三连接长期 IP 认知 | 从技巧上升到判断 |
| 01:15—01:35 | 保留检查标准和结束句 | 给用户一个可执行判断 |

## 六、T02/T03 脚本骨架

### T02：做个人 IP，不是把你知道的都讲出来

- 开头：如果你做内容时总觉得“我还有很多没讲”，这可能正是内容不清晰的原因。
- 核心观点：用户需要先理解一个问题，不需要一次拿走你的全部知识体系。
- 结构：知识堆积的表现 → 一条内容的最小单位 → 用一个专业案例说明 → 给出自检问题。
- 结束：下一条内容发布前，先删掉一半内容，看核心观点是否更清楚。
- 默认动作：收藏或继续观看同类内容。

### T03：一条口播只讲一个问题，为什么更容易被听懂？

- 开头：一条视频讲了五个观点，往往等于用户一个也没记住。
- 核心观点：内容不是知识目录，而是一次帮助用户完成判断的过程。
- 结构：问题 → 误区 → 一个判断标准 → 一个例子 → 下一步。
- 结束：检查标题、开头和结尾是否在回答同一个问题。
- 默认动作：保存这个结构，下次写稿时复用。
