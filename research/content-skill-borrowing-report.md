## 一、该 Skill 的核心流程

公开文档将写作拆成四个底层动作：

```text
明确希望读者产生的变化
→ 收集主题、受众、场景和证据
→ 只保留服务目标的信息
→ 决定表达方式、顺序和结构
```

它在写作前要求明确：

- 写作模式：说服型或信息型
- 内容类型：社交帖子、广告、报告等
- 格式限制：长度、渠道、语言和结构
- 读者：角色、问题、已有认知和怀疑
- 结束状态：读者最终要采取什么行动或形成什么认识
- 分发上下文：从哪里来、接下来做什么
- 语气限制：品牌、风格和禁用表达
- 可用资料：数据、案例、引用和证据
- 反目标：不应触碰的内容和约束

对于资料不足的情况，它明确要求研究、追问或使用带标签的占位符，不允许编造数字、客户、结果或细节。

## 二、对本项目八模块的映射

| Skill 的步骤 | 对应本项目模块 | 可借鉴结果 |
|---|---|---|
| 定义读者变化 | 业务与定位、客户与场景 | 每条内容先写目标，不直接写稿 |
| 收集受众/上下文/证据 | 客户与场景、渠道与流量 | 先研究账号、平台和用户问题 |
| 选择信息 | 内容与直播 | 控制内容主题，不堆工具和观点 |
| 设计结构和表达 | 内容与直播 | 先出结构方案，再进入文案 |
| 确认计划和语气 | 项目协作/人工审批 | 起草前交给项目发起人确认 |
| 自检和润色 | 数据复盘、交付 | 发布前做事实和表达审校 |
| 占位符而不编造 | 全模块 | 未知数据明确写“待补充” |

## 三、值得借鉴的机制

### 1. 研究优先

资料不足时不直接生成稿件。对本项目来说，内容写作前至少应有：

- 目标平台
- 目标受众假设
- 参考内容或研究资料
- 项目发起人的真实经验/案例
- 内容目标
- 不可承诺或不可公开的事项

### 2. 先给计划，再写正文

该 Skill 要求在正式起草前展示内容结构并获得确认。对应本项目：

```text
内容研究报告
→ 选题建议
→ 内容结构方案
→ 项目发起人确认
→ 模仿改写/原创写作
```

### 3. 先明确“读者看完之后的变化”

不能只写“做一条 AI 内容”，而要说明看完后希望读者：

- 留下具体问题
- 产生某种判断
- 采取私信、评论或预约行动
- 理解一个具体方法

### 4. 用证据代替空泛表达

案例、数字、客户原话、结果和具体场景必须有来源。没有就使用待补充标记，不用“明显提升”“大幅节省”等模糊表述代替。

### 5. 写作和改写是两种流程

新写内容前需要完整 brief；改写已有内容前，先诊断：

```text
目的与受众
→ 用户要求改善的维度
→ 成功标准
→ 不可改变部分
→ 清晰度/结构/具体性/说服力/语气/紧凑度诊断
→ 确认修正方向
→ 重写
```

这与本项目“先扒优质内容、先交分析报告、确认后模仿改写”直接相关。

## 四、不能直接照搬的地方

1. 该 Skill 是通用商业写作流程，不是抖音爆款方法。
2. 它没有证明任何具体选题会在抖音获得高播放或高转化。
3. 它没有替代对标账号研究、平台数据研究和内容表现复盘。
4. 它使用英文商业写作语境，中文口播的节奏、停顿和表达需要单独验证。
5. 它的 references 目录在公开目录中存在，但当前未取得全部参考文件内容，不能声称已完成完整复现。

## 五、纳入本项目的待确认版本

如果项目发起人确认，可将以下流程纳入“内容与直播”模块：

```text
确定内容目标
→ 明确受众和分发场景
→ 收集平台/对标/用户问题/个人案例
→ 标注证据和资料缺口
→ 提出选题和结构
→ 人工确认选题与结构
→ 模仿方法进行原创改写
→ 检查事实、案例、数字、版权和承诺
→ 生成发布稿
→ 人工发布
→ 记录评论、私信、预约和后续结果
```

## 六、建议确认的问题

- 是否同意把“先明确内容目标和读者变化”作为每条内容的必填字段？
- 是否同意资料不足时必须先研究或标记缺口，不直接生成看似完整的内容？
- 是否同意所有内容在起草前先提交结构方案确认？
- 是否同意先完成 Skill 方法借鉴确认，再进入抖音对标账号和优质内容扒取？
- 是否同意将这个 Skill 作为流程参考，而不是直接当成抖音内容生成器？

## 七、当前结论

**建议：借鉴流程，不直接安装或复制。**

它最有价值的不是“帮我们写出一条稿子”，而是提供了一个防止过早写作的工作纪律：

```text
目标先于选题
→ 资料先于文案
→ 结构先于正文
→ 确认先于起草
→ 证据先于承诺
```
