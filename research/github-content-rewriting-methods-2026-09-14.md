## 3. 综合为候选工作法（顾问归纳，待用户判断）

1. 提取原内容真正要解释的问题与核心观点，先不看能否成为爆款。
2. 分开检查观点质量与原内容传播表现，不因低赞直接淘汰，也不因高赞直接认可。
3. 将原内容拆成开头、问题/冲突、解释/证据和结论，标出各段功能；不要求所有稿件都用同一顺序。
4. 判断热点是否能自然解释同一个受众问题；核对事件事实与时间，不强行建立关联。
5. 生成多个入口候选：事件切入、常见误解切入、受众决策切入。后文用客户自己的知识与可验证材料重新组织。
6. 审核事实、推理、专业承诺和原创表达，避免从个别事件推出所有人的必然结果。
7. 人工选择后再测试；记录实际改动、输入、发布时间及可取得的数据，不能仅凭数据变化认定单个改动的因果效果。

## 4. C-001 三个示范方向（新写示例，不是历史原稿）

共同材料：用户转述的一条直播带货内容，涉及信任、供应链和复购；用户回忆相关人物带货的热点出现后进行了改写。人物身份、事件日期、“5000元”的销售口径均未核验，原稿与改稿关系仍未知。

### A：事件切入

结构：经核实的热点事件 → 人们可能得出的结论 → 重新提出业务问题 → 自己的解释。

演示开头：看到一个明星带货失利的案例，就能判断普通人都卖不动吗？先别急着下结论，我们把流量和持续经营分开看。

边界：此句仅演示结构，不能直接发布；实际使用前须核实所指事件、何谓失利及其是否适用。

### B：解释框架切入

结构：提出常见误解 → 引入分析维度 → 用自己的材料论证。

演示开头：判断自己该不该做直播带货，别只问“我有多少粉丝”。还可以检查三个问题：别人为什么信你、你能否稳定交付、客户为什么再次购买。

边界：这是顾问根据用户转述重新组织的分析框架，不声称是该领域唯一或完整的成功条件。

### C：受众决策切入

结构：点名目标人群 → 具体决策 → 自查动作 → 必要时引入已核实事件。

演示开头：如果你正准备第一次开播卖货，先拿一个具体产品回答：为什么找你买，出了问题谁处理，客户下一次还会不会需要它？

边界：提出供判断的问题，不承诺回答后一定成交；目标受众只是示范，不改变项目正式客户定位。
